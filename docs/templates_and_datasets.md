# About Templates

## 1. About Templates

#### 1a Accessing Templates

If you need templates to get started with, we have **[our pre-calculated templates](https://nyu.box.com/s/1gr9u1pw2twd3krbo60bin7m2yqat2pe)** under the `templates/` folder. Samples used to generate these templates are recorded from as many devices as we could aggregate, under various settings.

#### 1b. Naming Structure

Naming structure follows `<Recording Device>_<HMD>-<OS Version>`. For example, a template named `mqp_mqp-v2.1.1034` has the following characteristics:

- The video was recorded from the Meta Quest Pro directly, using its in-built Camera system.
- The calibration session that was recorded on video was also done on the same Meta Quest Pro, specifically, OS version 12.1.1034.

We currently have templates for different Meta devices. More are expected to be added soon.

#### 1c. Generalized Template Contents

Templates should contain the general structure:

- `calibration.json`: The calibration file that is generated by `src/calibrate.py` You must use this `.json` file to transform coordinates from VR screen space to video/frame space.
- `calibration.csv`: The original calibration targets used in the Unity calibration scene packaged with this repository.
- `cube.csv`: A test case that can be used to debug the accuracy of `calibration.json`, using `src/transform.py` and `src/video.py`.
- `capture.mp4`: Video recording of both the calibration session (to be referenced in `src/calibrate.py`) and a validation session with a blue cube (to be referenced in `src/video.py` in conjunction with `cube.csv`).
- `estimations/`: The output of `src/transform.py` using `cube.csv`.
- `calibrations/`: The output of `src/calibrate.py` using `calibration.csv` and `capture.mp4`.

## 2. About Analysis Datasets

#### 2a. Accessing Analysis Data

**[Datasets](https://nyu.box.com/s/1gr9u1pw2twd3krbo60bin7m2yqat2pe)** used in our [analysis of recording generalizability](analysis.md) are available alongside our templates, under the `analysis/` folder this time.

Note that this folder contains additional figures generated by our Python notebook, `src/analysis.ipynb`. For the actual data, they are listed in a subfolder called `data/`.

To put it simply, navigate to our [online data storage](https://nyu.box.com/s/1gr9u1pw2twd3krbo60bin7m2yqat2pe) and look under `analysis/data/`.

#### 2b. Naming Structure

The naming structure of each folder can be subdivided into the following regular pattern: 

```
<IPD>-<DYN. RES>-<DEVICE>
```

For example, `58-yes-android` indicates that this session was recorded with a 58mm IPD with dynamic resolution toggled and recorded on an Android device.

For `<DEVICE>` definitions, observe the table below:

|Display Device|Resolution|Recording Methodology|
|:-|:-|:-|
|PC w/ Horizontal Monitor|`2560px` x `1080px`|Web Casting ([www.oculus.com/casting](www.oculus.com/casting)) + OBS|
|PC w/ Vertical Monitor|`1080px` x `1920px`|Web Casting ([www.oculus.com/casting](www.oculus.com/casting)) + OBS|
|Mac M1 Pro|`1512px` x `982px`|Web Casting ([www.oculus.com/casting](www.oculus.com/casting)) + QuickTime Player|
|iPhone XR|`1792px` x `828px`|[Meta Horizon App](https://apps.apple.com/us/app/meta-horizon/id1366478176), comes with a built-in recording feature|
|Motorola Razr Plus 2024|`2640px` x `1080px`|[Meta Horizon App](https://play.google.com/store/apps/details?id=com.oculus.twilight&hl=en_US), comes with a built-in recording feature|

#### 1c. Generalized Folder Contents

Each directory in `analysis/data/` contains the following files:

- `events.csv`: All relevant timestamps in each trial, from trial initialization to when each gaze target is rendered on the screen.
- `gaze_targets.csv`: The world and screen positions of each gaze target. 
    - `events.csv` and `gaze_targets.csv` can be merged via the common key column `target_number`.
- `video.mp4`: Recording of the calibration session.
- `frames/`: Each gaze target extracted as a single frame image from `video.mp4`. Not annotated.
- `anchor_frames/`: Each frame from `frames/` annotated with the estimated video space target based on that trial's estimated transformation matrix. Used mainly for visual validation of the accuracy of the aforementioned transformation matrix.
